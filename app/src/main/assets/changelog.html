v2026.8.4.v2

  • Fixed a bug where erasing strokes and then rotating the screen could make the deleted strokes reappear. After an erase, the only save attempt was the one fired in onPause() just before the rotate-recreate, and that save ran as a child of the activity's lifecycleScope, which Android cancels when the activity is destroyed. If the Dispatchers.IO worker hadn't picked the job up yet when onDestroy fired, the save was yanked before its body ran, the ink file on disk was never updated, and the new activity decoded the pre-erase strokes, bringing the deleted ink back. Saves now run on an application-scoped supervisor (appSaveScope) that is not cancelled by activity destruction, onDestroy pins the in-flight write on a background thread until it lands, and loadSavedDrawingNow() joins any still-running save before reading the ink file, so the post-erase state always reaches disk before anything reads it back.

v2026.8.2

  • Fixed a bug where fast-dragging the side scroll pill in a long PDF froze the app and triggered repeated "Application Not Responding" dialogs. Each touch-move event used to issue its own giant scrollBy plus dozens of page binds on the main thread, fast enough to overrun Android's 5-second input-dispatch window. The move handler now coalesces into a single scrollBy per Choreographer frame, the engine's size-prefetch sweep and the zoomed-in hi-res tile renderer stand down for the duration of the drag so the single render thread is dedicated to whichever page you land on, and the per-page "last viewed page" persistence is deferred until scrolling actually stops instead of firing on every page crossing.
